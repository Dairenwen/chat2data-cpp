# 依赖库手册

## 1. 路径与准备

### 1.1 选择执行环境

优先在已经配好 C++ 依赖的开发容器中操作。开发环境的启动、进入容器和网络说明见仓库根目录的 [README](../../README.md)。如果直接在宿主机操作，宿主机也需要具备相同的头文件和库。

在包含 `chat2data-cpp/` 和 `libSource/` 的 **workspace 目录**执行下面的初始化命令。容器内通常是 `/home/dev/workspace`；宿主机当前目录是 `/home/drw/workspace/bite-dev-environment/dev-environment/workspace`。

```bash
# 先进入实际 workspace，再执行；保留此终端中的变量供后续步骤使用
export CHAT2_WORKSPACE="$(pwd)"
export CHAT2_LIBSOURCE="$CHAT2_WORKSPACE/libSource"
export CHAT2_DEP_BUILD="$CHAT2_WORKSPACE/.dependency-build"
export CHAT2_DEP_PREFIX="$CHAT2_WORKSPACE/.dependency-prefix"

test -d "$CHAT2_WORKSPACE/chat2data-cpp/chat2excel"
test -d "$CHAT2_LIBSOURCE/AIModelAcessTech/sdk"
test -d "$CHAT2_LIBSOURCE/OpenXLSX"
test -d "$CHAT2_LIBSOURCE/cpp-microservice-scaffold/source"

g++ --version
cmake --version
```

目录检查退出码应为 0。最低通用要求是支持 C++17 的编译器和 CMake 3.15；如果系统 CMake 对旧项目的兼容性报错，先看第 7 节，不要直接改第三方源码。

### 2.2 读取一个真实文件的最小示例

以下是**独立学习示例**，仅列出工作表名称并读取第一张工作表的 `A1`。它没有实现整个工作表提取或 chat2excel 解析器。

在第 1 节变量仍有效的终端中，创建临时学习目录：

```bash
export CHAT2_XLSX_DEMO="$(mktemp -d /tmp/chat2excel-xlsx-demo.XXXXXX)"
cd "$CHAT2_XLSX_DEMO"
```

保存以下内容为该临时目录中的 `main.cpp`：

```cpp
#include <OpenXLSX.hpp>
#include <exception>
#include <iostream>

int main(int argc, char** argv) {
    if (argc != 2) {
        std::cerr << "用法：xlsx_demo 文件.xlsx\n";
        return 1;
    }
    try {
        OpenXLSX::XLDocument doc;
        doc.open(argv[1]);
        const auto names = doc.workbook().worksheetNames();
        for (const auto& name : names) {
            std::cout << "工作表：" << name << '\n';
        }
        if (!names.empty()) {
            auto sheet = doc.workbook().worksheet(names.front());
            const OpenXLSX::XLCellValue value = sheet.cell("A1").value();
            // 输出运算符可显示不同值类型，避免强制把数值当作字符串读取
            std::cout << "A1（" << value.typeAsString() << "）："
                      << value << '\n';
        }
        doc.close();
    } catch (const std::exception& e) {
        std::cerr << "读取失败：" << e.what() << '\n';
        return 1;
    }
}
```

保存以下内容为同目录中的 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.15)
project(xlsx_demo LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(OPENXLSX_ENABLE_LTO OFF CACHE BOOL "" FORCE)
add_subdirectory("${CHAT2_LIBSOURCE}/OpenXLSX/OpenXLSX" openxlsx)
add_executable(xlsx_demo main.cpp)
target_link_libraries(xlsx_demo PRIVATE OpenXLSX::OpenXLSX)
```

然后执行：

```bash
cmake -S "$CHAT2_XLSX_DEMO" -B "$CHAT2_XLSX_DEMO/build" \
  -DCHAT2_LIBSOURCE="$CHAT2_LIBSOURCE" -DCMAKE_BUILD_TYPE=Release
cmake --build "$CHAT2_XLSX_DEMO/build" --parallel 2

# 替换成实际存在的 .xlsx 文件绝对路径
"$CHAT2_XLSX_DEMO/build/xlsx_demo" /absolute/path/to/sample.xlsx
```

预期输出 worksheet 名称、`A1` 的类型与内容。后续若要提取表格，可按 `sheet.rowCount()`、`columnCount()` 遍历，并依据 `value.type()` 选择 `get<int64_t>()`、`get<double>()`、`get<bool>()`、`get<std::string>()`，同时处理空值和错误值。行列编号从 1 开始，遍历范围还应设置业务上限。

## 3. ChatSDK：构建、初始化、创建会话、发送消息

### 3.1 单独构建并安装 SDK

SDK 使用现有构建入口，安装到 workspace 的独立前缀，不要求写入系统 `/usr/local`。

```bash
cmake -S "$CHAT2_LIBSOURCE/AIModelAcessTech/sdk" \
  -B "$CHAT2_DEP_BUILD/sdk" \
  -DCMAKE_INSTALL_PREFIX="$CHAT2_DEP_PREFIX"
cmake --build "$CHAT2_DEP_BUILD/sdk" --parallel 2
cmake --install "$CHAT2_DEP_BUILD/sdk"

test -f "$CHAT2_DEP_PREFIX/lib/libai_chat_sdk.a"
test -f "$CHAT2_DEP_PREFIX/include/ai_chat_sdk/ChatSDK.h"
```

SDK 的 CMake 文件没有显式 `project()`，单独配置时可能出现 CMake 警告；这与模型连接无关。现有配置固定 `Debug`，不要以为传入 `Release` 就一定改变了构建类型。

### 3.2 普通回复和流式回复示例

以下示例使用本地源码支持的 `deepseek-chat` 配置。模型名与请求格式来自当前 Provider，运行时是否成功还取决于服务端、网络和 Key。

创建临时学习目录：

```bash
export CHAT2_SDK_DEMO="$(mktemp -d /tmp/chat2excel-sdk-demo.XXXXXX)"
cd "$CHAT2_SDK_DEMO"
```

保存为 `main.cpp`：

```cpp
#include <ai_chat_sdk/ChatSDK.h>
#include <ai_chat_sdk/util/myLog.h>
#include <cstdlib>
#include <iostream>
#include <memory>
#include <string>
#include <vector>

int main() {
    const char* key = std::getenv("deepseek_apikey");
    if (!key || !*key) {
        std::cerr << "请先设置 deepseek_apikey\n";
        return 1;
    }
    // 必须在构造 SDK 之前初始化：构造期间数据库代码会记录日志
    bite::Logger::initLogger("sdk_demo", "stdout", spdlog::level::warn);
    ai_chat_sdk::ChatSDK sdk;
    auto config = std::make_shared<ai_chat_sdk::APIConfig>();
    config->_modelName = "deepseek-chat";
    config->_apiKey = key;
    config->_temperature = 0.7;
    config->_maxTokens = 512;
    sdk.initModels({config});

    bool found = false;
    for (const auto& model : sdk.getAvailableModels()) {
        if (model._modelName == config->_modelName && model._isAvailable) {
            found = true;
        }
    }
    if (!found) {
        std::cerr << "目标模型没有完成本地初始化\n";
        return 1;
    }
    const auto sessionId = sdk.createSession(config->_modelName);
    if (sessionId.empty()) return 1;

    const auto reply = sdk.sendMessage(sessionId, "请用一句话介绍你能做什么。");
    if (reply.empty()) {
        std::cerr << "普通请求未获得回答，请检查配置和网络\n";
        return 1;
    }
    std::cout << "普通回复：" << reply << '\n';

    const auto fullReply = sdk.sendMessageStream(
        sessionId, "请用两句话说明怎样阅读一张销售数据表。",
        [](const std::string& chunk, bool done) {
            std::cout << chunk << std::flush;
            if (done) std::cout << '\n';
        });
    if (fullReply.empty()) {
        std::cerr << "流式请求未获得回答\n";
        return 1;
    }
}
```

保存为 `CMakeLists.txt`，使用刚才安装的 SDK：

```cmake
cmake_minimum_required(VERSION 3.15)
project(sdk_demo LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
find_package(OpenSSL REQUIRED)
find_package(Threads REQUIRED)
find_path(CHAT2_SDK_INCLUDE ai_chat_sdk/ChatSDK.h
          HINTS "${CHAT2_DEP_PREFIX}/include")
find_library(CHAT2_SDK_LIBRARY ai_chat_sdk
             HINTS "${CHAT2_DEP_PREFIX}/lib")
if(NOT CHAT2_SDK_INCLUDE OR NOT CHAT2_SDK_LIBRARY)
    message(FATAL_ERROR "请先安装 SDK 并传入 CHAT2_DEP_PREFIX")
endif()
add_executable(sdk_demo main.cpp)
target_include_directories(sdk_demo PRIVATE "${CHAT2_SDK_INCLUDE}")
target_compile_definitions(sdk_demo PRIVATE CPPHTTPLIB_OPENSSL_SUPPORT)
target_link_libraries(sdk_demo PRIVATE "${CHAT2_SDK_LIBRARY}"
    jsoncpp fmt spdlog sqlite3 OpenSSL::SSL OpenSSL::Crypto Threads::Threads)
```

构建，然后通过交互方式输入自己的 Key：

```bash
cmake -S "$CHAT2_SDK_DEMO" -B "$CHAT2_SDK_DEMO/build" \
  -DCHAT2_DEP_PREFIX="$CHAT2_DEP_PREFIX"
cmake --build "$CHAT2_SDK_DEMO/build" --parallel 2

read -r -s -p '输入 DeepSeek API Key: ' deepseek_apikey
export deepseek_apikey

# 在临时学习目录运行，chatDB.db 会写在这里
cd "$CHAT2_SDK_DEMO"
"$CHAT2_SDK_DEMO/build/sdk_demo"
```

预期先显示普通回复，再逐步显示流式回复。非空返回值只是基础判断：部分 Provider 也可能返回错误描述字符串；排错时还需检查日志、HTTP 状态和回答内容。

### 3.3 换成本地 Ollama

SDK 示例中的模型配置也可以替换为：

```cpp
auto config = std::make_shared<ai_chat_sdk::OllamaConfig>();
config->_modelName = "deepseek-r1:1.5b"; // 示例名，必须是服务中实际已部署的模型
config->_modelDesc = "本地模型";
config->_endpoint = "http://localhost:11434";
config->_temperature = 0.7;
config->_maxTokens = 512;
sdk.initModels({config});
```

使用此配置时，删除普通示例中的云端 Key 检查和赋值，其他会话与发送流程相同。Ollama 服务和模型需要预先准备；本手册没有安装或启动它们。

容器中的 `localhost` 指向**当前容器**，只有服务确实运行在当前容器时才能用这个地址。模型服务在其他容器或宿主机时，需要填写从当前容器可访问的地址。SDK 的 Ollama Provider 将 `_maxTokens` 映射成 `num_ctx`，在此源码中它不是输出令牌上限。

源码入口：[ChatSDK.h](../../../libSource/AIModelAcessTech/sdk/include/ChatSDK.h)、[common.h](../../../libSource/AIModelAcessTech/sdk/include/common.h)、[ChatSDK.cpp](../../../libSource/AIModelAcessTech/sdk/src/ChatSDK.cpp)。

## 4. bite_scaffold：从 JSON、文件和日志工具开始

### 4.1 最小用法

单独编译 `util.cc` 和 `log.cc` 可以学习与 Excel 流程直接相关的工具，不需要先准备全部中间件依赖。

```bash
export CHAT2_UTIL_DEMO="$(mktemp -d /tmp/chat2excel-util-demo.XXXXXX)"
cd "$CHAT2_UTIL_DEMO"
```

保存为 `main.cpp`：

```cpp
#include "util.h"
#include "log.h"
#include <iostream>

int main() {
    bitelog::bitelog_init();
    Json::Value table;
    table["sheet"] = "销售表";
    table["rows"] = Json::Value(Json::arrayValue);
    Json::Value row;
    row["product"] = "示例商品";
    row["amount"] = 120;
    table["rows"].append(row);

    const auto text = biteutil::JSON::serialize(table);
    if (!text) return 1;
    // 会覆盖同名文件；本例在独立临时目录中运行
    if (!biteutil::FUTIL::write("table.json", *text)) return 1;
    std::string body;
    if (!biteutil::FUTIL::read("table.json", body)) return 1;
    const auto parsed = biteutil::JSON::unserialize(body);
    if (!parsed) return 1;

    INF("已完成 JSON 和文件读写示例");
    std::cout << (*parsed)["sheet"].asString() << '\n';
    std::cout << body << '\n';
}
```

编译并在该临时目录中运行：

```bash
g++ -std=c++17 -pthread \
  -I"$CHAT2_LIBSOURCE/cpp-microservice-scaffold/source" \
  "$CHAT2_UTIL_DEMO/main.cpp" \
  "$CHAT2_LIBSOURCE/cpp-microservice-scaffold/source/util.cc" \
  "$CHAT2_LIBSOURCE/cpp-microservice-scaffold/source/log.cc" \
  -o "$CHAT2_UTIL_DEMO/util_demo" \
  -ljsoncpp -lfmt -lspdlog

cd "$CHAT2_UTIL_DEMO"
./util_demo
```

预期生成 `table.json`，显示“销售表”和序列化内容。这只是工具用法演示；表格内容由示例手动构造，没有执行 Excel 提取。

### 4.2 常用接口速查

| 需求          | 调用方式                               | 需要检查                                   |
| ------------- | -------------------------------------- | ------------------------------------------ |
| JSON 序列化   | `biteutil::JSON::serialize(value)`   | `optional` 是否有值。                    |
| JSON 反序列化 | `biteutil::JSON::unserialize(text)`  | `optional` 是否有值。                    |
| 读整个文件    | `biteutil::FUTIL::read(path, body)`  | 返回`bool`；不是 Excel 结构解析。        |
| 写整个文件    | `biteutil::FUTIL::write(path, body)` | 返回`bool`；覆盖写入，父目录需提前存在。 |
| 初始化日志    | `bitelog::bitelog_init(settings)`    | 必须早于调用日志宏和可能记录错误的工具。   |
| 日志输出      | `INF("结果：{}", result)`            | 使用 fmt 风格的占位符。                    |

源码入口：[util.h](../../../libSource/cpp-microservice-scaffold/source/util.h)、[log.h](../../../libSource/cpp-microservice-scaffold/source/log.h)。

## 5. 可选：体验现有 HTTP 聊天与 SSE 参考服务

这一步运行的是 `AIModelAcessTech` 的 **AIChatServer**，提供聊天示例，没有 Excel 上传/解析能力。先完成第 3.1 节 SDK 安装，并准备 gflags 和至少一个有效的云端模型 Key。

### 5.1 构建与运行目录

现有服务的 CMake 偏向 `/usr/local` 安装布局。使用前面独立安装前缀时，显式传入头文件和库搜索路径：

```bash
cmake -S "$CHAT2_LIBSOURCE/AIModelAcessTech/ChatServer" \
  -B "$CHAT2_DEP_BUILD/chatserver" \
  -DCMAKE_CXX_FLAGS="-I$CHAT2_DEP_PREFIX/include" \
  -DCMAKE_EXE_LINKER_FLAGS="-L$CHAT2_DEP_PREFIX/lib"
cmake --build "$CHAT2_DEP_BUILD/chatserver" --parallel 2

# 服务从运行目录中的 ./www 加载静态页面
mkdir -p "$CHAT2_DEP_BUILD/chatserver-run"
cp -R "$CHAT2_LIBSOURCE/AIModelAcessTech/ChatServer/build/www" \
  "$CHAT2_DEP_BUILD/chatserver-run/"
cd "$CHAT2_DEP_BUILD/chatserver-run"
```

以上搜索路径写法适用于当前不含空格的 workspace 路径。独立 SDK 调用示例中的 `find_path/find_library` 方案更适合后续可移植的构建配置。

### 5.2 Key 和端口

`main.cpp` 实际读取的环境变量区分大小写：

| Provider | 参考服务实际读取的变量 |
| -------- | ---------------------- |
| DeepSeek | `deepseek_apikey`    |
| ChatGPT  | `chatgpt_apikey`     |
| Gemini   | `gemini_apikey_new`  |

源码帮助文字中出现的 `DEEPSEEK_API_KEY` 与实际读取变量不一致，应以表格为准。下面以 DeepSeek 为例：

```bash
read -r -s -p '输入 DeepSeek API Key: ' deepseek_apikey
export deepseek_apikey

"$CHAT2_DEP_BUILD/chatserver/AIChatServer" --host=0.0.0.0 --port=9000
```

默认端口是 `8080`。使用仓库开发环境时，预留映射包含 `9000–9009`，所以此例显式使用 `9000`；先确认端口没有被其他进程占用。从宿主机浏览器访问 `http://localhost:9000`，若 Docker 在远程机器中则使用该机器可访问的地址。

服务将 `chatDB.db` 写入运行目录。结束参考服务时使用当前终端的 `Ctrl+C`。

如果要用配置文件，在运行目录创建例如 `demo.conf`：

```text
--host=0.0.0.0
--port=9000
--log_level=INFO
--temperature=0.7
--max_tokens=512
```

使用 gflags 的明确加载方式：

```bash
"$CHAT2_DEP_BUILD/chatserver/AIChatServer" --flagfile=./demo.conf
```

Key 仍通过环境变量提供。不要只依赖源码中 `--config_file` 的自动加载逻辑。纯 Ollama、三个云端 Key 都为空时，当前服务的校验会拒绝启动；可单独使用第 3.3 节 SDK 示例。

### 5.3 用接口观察 SSE

服务保持运行时，在另一个终端执行：

```bash
curl http://localhost:9000/api/models

curl -X POST http://localhost:9000/api/session \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-chat"}'
```

从创建会话的 JSON 响应中取得 `data.session_id`，将下方 `实际会话ID` 替换为该值：

```bash
curl -N -X POST http://localhost:9000/api/message/async \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"实际会话ID","message":"请简要介绍你能做什么。"}'
```

参考服务的 SSE 数据形态如下，每条事件以一个空行结束：

```text
data: "回答片段"

data: "后续片段"

data: [DONE]

```

片段是 JSON 字符串，需要解码后展示；`[DONE]` 是独立的结束标记。此接口使用 POST，参考页面使用 `fetch` 读取响应流，并非直接用原生 `EventSource` 发送 POST。

| 方法与路径                                | 作用                                            |
| ----------------------------------------- | ----------------------------------------------- |
| `POST /api/session`                     | 创建会话，请求包含`model`。                   |
| `GET /api/sessions`                     | 获取会话列表。                                  |
| `GET /api/models`                       | 获取已被标记为可用的模型列表。                  |
| `GET /api/session/{session_id}/history` | 获取会话历史。                                  |
| `DELETE /api/session/{session_id}`      | 删除指定会话。                                  |
| `POST /api/message`                     | 普通回复，请求包含`session_id`、`message`。 |
| `POST /api/message/async`               | SSE 流式回复，请求字段同上。                    |

源码入口：[ChatServer.cpp](../../../libSource/AIModelAcessTech/ChatServer/ChatServer.cpp)、[main.cpp](../../../libSource/AIModelAcessTech/ChatServer/main.cpp)、[前端 script.js](../../../libSource/AIModelAcessTech/ChatServer/build/www/script.js)。

## 7. 常见问题

| 现象                                          | 优先检查                                                                                                                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 找不到目录                                    | 实际名称是`libSource`、`AIModelAcessTech`；确认变量是从 workspace 初始化的。                                                                                          |
| 找不到`httplib.h` / JsonCpp / spdlog 头文件 | 当前宿主机或容器是否安装开发头文件，搜索路径是否正确。                                                                                                                    |
| `cannot find -lai_chat_sdk`                 | 第 3.1 节是否安装成功，链接路径是否指向相同安装前缀。                                                                                                                     |
| CMake 报旧版本兼容性已移除                    | 脚手架声明最低版本 3.1.3。使用支持旧配置的 CMake；若错误信息建议，可以在配置命令中加`-DCMAKE_POLICY_VERSION_MINIMUM=3.5` 再检查后续结果，此选项不保证解决其他兼容问题。 |
| 脚手架报“丢失关键依赖库”                    | 完整构建会检查所有中间件依赖；只学习工具时先用第 4.1 节。                                                                                                                 |
| `find_package(bite_scaffold)` 报目标未构建  | 查看包配置中的`find_my_depends()` 与 `${PROJECT_NAME}` 使用顺序；不能把它当成业务代码错误。                                                                           |
| SDK 构造时异常或崩溃                          | 是否在创建 SDK 前初始化`bite::Logger`，运行目录是否可写入 SQLite。                                                                                                      |
| 初始化成功但回答为空                          | 初始化返回值和模型列表不是远端连通性检查；检查模型名、Key、网络和 Provider 日志。                                                                                         |
| Ollama 连不上                                 | endpoint 必须从调用程序所在环境可访问；容器`localhost` 不是宿主机。                                                                                                     |
| 参考服务拒绝纯 Ollama 配置                    | 当前校验还要求至少一个云端 Key 非空；先使用 SDK 的 Ollama 示例。                                                                                                          |
| 网页打不开但服务进程存在                      | 检查`./www`、实际监听端口、容器端口映射；`isRunning()` 不能单独证明监听已成功。                                                                                       |
| SSE 没有持续显示                              | 使用`curl -N` 或读取响应流；保留事件空行，解码 JSON 字符串，识别 `[DONE]`。                                                                                           |
| `get<std::string>()` 读取单元格时报类型错误 | 根据单元格实际类型取值；日期、公式、空值也需要分别处理。                                                                                                                  |
