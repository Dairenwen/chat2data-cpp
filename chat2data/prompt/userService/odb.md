# 用户子服务 ODB 数据库映射

**系统身份：** 你是一名熟悉 C++、MySQL 和 ODB 的后端开发工程师。

**任务：** 为用户子服务编写 ODB 数据库表映射类，完成用户表和登录会话表的 C++ 类映射，并使用 CMake 完成映射代码和建表 SQL 的生成及编译。

用户表和会话表的字段以项目中的[数据库设计](../../docs/数据库设计.md)为准；用户服务的整体设计参见 [userService.md](./userService.md)。`data` 目录中已包含用户表和会话表的 ODB 映射实现。

## 用户表设计

| 字段         | 类型            | 约束 | 备注                  |
| ------------ | --------------- | ---- | --------------------- |
| `id`       | BIGINT UNSIGNED | PK   | 自增主键              |
| `userId`   | VARCHAR(32)     | UNI  | 用户业务 ID，必须唯一 |
| `nickname` | VARCHAR(32)     | UNI  | 用户昵称，必须唯一    |
| `email`    | VARCHAR(255)    | UNI  | 用户邮箱，必须唯一    |
| `password` | TEXT            |      | 存储带盐的密码哈希    |
| `status`   | INT             |      | 登录状态或离线状态    |

**注意事项：**

- 用户密码只存储带盐的密码哈希，不存储明文密码。
- 用户 ID、昵称和邮箱分别建立唯一约束，支持按用户 ID、昵称和邮箱查询。
- 用户状态按照项目数据库设计使用 `INT`；目前只规定登录状态和离线状态。

## 登录会话表设计

| 字段          | 类型            | 约束 | 备注                          |
| ------------- | --------------- | ---- | ----------------------------- |
| `id`        | BIGINT UNSIGNED | PK   | 自增主键                      |
| `sessionId` | VARCHAR(32)     | UNI  | 登录会话 ID，必须唯一         |
| `userId`    | VARCHAR(32)     |      | 所属用户 ID                   |
| `expiresAt` | BIGINT UNSIGNED |      | Unix 毫秒，到期后不能用于认证 |

**注意事项：**

- 会话 ID 必须唯一；用户 ID 可以重复，以支持同一用户在多个设备登录。
- 过期时间是项目数据库设计中的字段，应包含在映射类和生成的 SQL 中。
- 参考图片要求会话字段为 `NOT NULL`；过期时间用于判断会话有效性，本任务同样按非空字段生成。
- 本表保存登录会话，与 AI 聊天会话分开。

## 实现要求

1. 编写 ODB 数据库表映射类：

   - 用户表映射类命名为 `UserEntity`，表名为 `tbl_user`，头文件为 `data/userEntity.hpp`。
   - 登录会话表映射类命名为 `SessionEntity`，表名为 `tbl_session`，头文件为 `data/sessionEntity.hpp`。
   - 两个类放入 `chat2Data` 命名空间，按照上面的字段、类型和约束进行映射。
   - 用户表中的用户 ID、昵称、邮箱，以及会话表中的会话 ID，分别对应数据库唯一约束。
   - 用户表和会话表的 `ID` 对应数据库自增主键；会话表的用户 ID 不设置唯一约束。
   - 业务密码在持久化前转换为带盐密码哈希，映射类只负责保存哈希值。
   - 需要保证中文字符能够完整存储，指定正确的字符集以及存储引擎。
2. 编写映射类的 CMake 构建配置：

   - 在 `CMakeLists.txt` 中配置 ODB 代码和建表 SQL 的生成及编译，并将该目录接入项目根目录的 CMake 构建。
   - ODB 生成的 C++ 映射代码放在 `data/odb` 目录，生成的 SQL 放在 `data/sql` 目录。
   - CMake 应追踪映射头文件的变化，使修改后可以重新生成相应文件；已有网关和公共库构建保持可用。
   - 使用项目现有的 C++17 和开发容器，参考 `cpp-service-kit` 已有的 ODB、MySQL 依赖配置；不要修改 `cpp-service-kit` 中的文件。
   - 生成 SQL 后生成一个建表脚本；
3. 验证生成结果：

   - 在 `dev-env-service` 容器中以 `dev` 用户完成 CMake 配置和构建。
   - 检查两个映射类均能通过 ODB 生成和 C++ 编译。
   - 检查生成的 SQL 包含两张表的字段、类型、主键和唯一约束，尤其是会话过期时间和允许重复的用户 ID。
   - 确认现有公共库和网关仍能构建，并说明实际执行的验证结果。

先阅读 `mustRead` 目录，再仔细阅读用户表和登录会话表的设计，按照以上要求完成映射和编译；**实现范围限于 ODB 映射及其构建，不在本任务中实现用户 RPC、Redis 缓存或用户业务逻辑。**
