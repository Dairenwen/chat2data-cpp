# 业务分析

## 1. 页面功能点分析

使用 Chat2Data 前，用户需要完成注册和登录。登录成功后，才能通过自然语言与 Excel 文件或数据库交互。系统的核心页面包括注册、登录、导航栏、智能 Excel、智能 DB、我的文件、历史会话和个人信息。

### 1.1 注册页面

#### 1.1.1 注册信息与基本流程

首次使用 Chat2Data 的用户，需要先注册账号。注册页面要求提供以下信息：

- **用户昵称**：支持后续使用昵称登录。
- **用户邮箱**：作为注册信息，同时用于邮箱验证码登录。
- **用户密码与确认密码**：密码至少 8 位，且在数字、字母、特殊字符中至少包含两种类型；确认密码应与密码一致。

用户填写信息后点击“注册”，浏览器向后端发送注册请求，由服务端校验信息并完成账号注册。

#### 1.1.2 唯一性校验

- **昵称唯一性**：由于 Chat2Data 支持昵称登录，昵称不能与已有用户重复。输入昵称后，后端检查是否已被使用；若重复，用户需要重新输入未被使用的昵称。
- **邮箱唯一性**：由于 Chat2Data 支持邮箱验证码登录，邮箱不能重复注册。输入邮箱后，后端检查是否已有对应账号；若重复，用户需要更换邮箱。

#### 1.1.3 涉及的服务端功能

1. 检测用户昵称是否唯一。
2. 检测邮箱是否唯一。
3. 用户注册。

### 1.2 登录页面

#### 1.2.1 支持的登录方式

系统提供三种登录方式：

| 登录方式           | 用户操作                                 | 服务端处理                           |
| ------------------ | ---------------------------------------- | ------------------------------------ |
| 昵称或邮箱密码登录 | 输入昵称或注册邮箱，以及注册时设置的密码 | 校验账号与密码是否匹配               |
| 邮箱验证码登录     | 输入注册邮箱，获取验证码并在有效期内提交 | 发送验证码，并校验用户提交的验证码   |
| 会话登录           | 浏览器使用先前缓存的会话 ID 发起登录     | 判断会话 ID 是否有效，并识别对应用户 |

**密码登录：** 用户填写昵称或邮箱和密码，提交后由服务端完成校验，匹配成功即登录。

**邮箱验证码登录：** 用户填写注册邮箱并点击“获取验证码”。后端将验证码发送到该邮箱，验证码在 **5 分钟** 后失效；用户在有效期内输入验证码即可完成登录。

#### 1.2.2 会话登录机制

用户首次登录成功后，服务端会返回一个登录会话 ID（`sessionId`），浏览器在客户端保存该 ID。再次打开页面时，浏览器先尝试使用此前缓存的会话 ID 登录。

设定的会话有效期为 **3 天**。只要会话 ID 仍处于有效期内，服务端就可以识别用户并完成会话登录；失效时则进入普通登录流程。

#### 1.2.3 登录成功后的初始化操作

登录成功后跳转至主页面。进入主页面之前，浏览器主动请求：

1. **获取当前用户的个人信息**：包括用于界面显示的用户昵称等。
2. **获取平台支持的模型列表**：供用户在聊天区域选择。

主页面默认选中“智能 Excel 助手”，页面右上角显示当前登录用户的昵称，聊天区域下方显示可用模型。

#### 1.2.4 登录页面涉及的服务端功能

1. 昵称（邮箱）密码登录。
2. 获取邮箱验证码。
3. 验证码登录。
4. 会话登录。
5. 获取用户信息。
6. 获取支持的模型列表。

#### 1.2.5 关于选择邮箱验证码的业务说明

比较阿里云、腾讯云和华为云等短信服务平台，指出短信签名与企业实名资质审核要求限制了个人身份接入短信验证服务的可行性，并提及当时华为云相关短信服务的变化。因此，**该项目选择通过邮箱接收验证码**。

### 1.3 导航栏

用户登录后进入主界面，导航栏负责切换不同的业务模块。**页面跳转行为由前端实现**。

| 导航项          | 页面功能                                                 |
| --------------- | -------------------------------------------------------- |
| 智能 Excel 助手 | 上传和预览 Excel 文件，通过自然语言分析、操作 Excel 数据 |
| 智能 DB 助手    | 连接 MySQL 或 SQLite 数据库，通过自然语言操作数据库表    |
| 我的文件        | 查看已上传文件，执行预览、下载、删除等操作               |
| 历史会话        | 查看聊天会话列表，打开会话并查看历史内容                 |
| 个人中心        | 查看当前用户个人信息及其上传的文件                       |

### 1.4 智能 Excel 页面

#### 1.4.1 页面布局

智能 Excel 页面分为两个主要区域：

- **文件预览与数据可视化区域**：展示 Excel 数据、表结构，以及模型返回的总结和图表。
- **聊天消息区域**：展示用户与模型的对话，提供模型选择、消息输入、发送及新建会话等操作。

#### 1.4.2 新建会话与模型选择

用户与模型聊天前，必须先创建一个聊天会话。点击“新建会话”后，服务端创建会话并返回会话 ID；本轮聊天中的消息归属该会话。

页面提供模型列表下拉框，展示系统支持的模型。用户在创建新会话前选择具体模型，以确定后续聊天所使用的模型。

#### 1.4.3 Excel 文件上传与存储

创建会话后，用户可以使用文件上传按钮。点击按钮时，打开文件选择窗口，用户选择 Excel 文件并上传。

上传后，服务端执行以下处理：

1. 接收并保存 Excel 文件，文档中说明可在服务器中保存文件副本。
2. 解析 Excel 中各个 `Worksheet` 的内容。
3. 按 `Worksheet` 为单位存储数据：**一个 Worksheet 对应 MySQL 中的一张表**。
4. 建立 Excel 文件和解析结果之间的关联，便于后续预览与自然语言查询。

原文还区分了两种聊天情况：

- **未上传 Excel 文件直接发送消息**：作为普通模型聊天处理。
- **上传 Excel 文件后发送消息**：针对已上传文件中的数据进行交互和分析。

#### 1.4.4 Excel 文件预览

文件上传成功后，客户端立即发送预览请求。服务端查询与该 Excel 文件关联的数据库表，返回**表结构及表数据**。客户端收到数据后，在文件预览区域展示解析内容，供用户查看。

#### 1.4.5 发送自然语言问题与结果分析

用户在消息编辑框输入针对 Excel 的问题，点击发送按钮后，浏览器将问题提交至后端。服务端结合用户问题和数据表信息与模型交互，执行生成的 SQL，然后将 SQL 结果交由模型总结。

结果分析区域主要呈现两类内容：

- **分析总结文字**：根据用户问题及 SQL 执行结果生成的文字结论。
- **数据可视化内容**：根据分析结果生成的可视化展示，例如图表。

聊天消息区域用于查看用户输入和模型响应；文件预览区域用于查看数据本身，两者共同组成 Excel 数据交互页面。

#### 1.4.6 文件与聊天会话的关联

同一个 Excel 文件可能对应多个聊天会话。用户分析完某类问题后，可以重新创建新会话，再将已有 Excel 文件关联到新会话。

这一设计使用户能够：

1. 继续使用之前上传的 Excel 数据。
2. 在新会话中发起不同的数据分析问题。
3. 将新会话的消息与之前的历史消息分开管理。

因此，除了上传和预览 Excel，服务端还需要提供**关联 Excel 文件和聊天会话**的功能。

#### 1.4.7 智能 Excel 涉及的服务端功能

1. 新建会话。
2. 上传文件信息。
3. 上传 Excel 文件数据。
4. 预览 Excel 文件。
5. 给模型发送消息。
6. 关联 Excel 文件和聊天会话。

### 1.5 智能 DB 页面

智能 DB 页面用于通过自然语言与数据库交互，原文支持 **MySQL** 和 **SQLite** 两种数据库。

#### 1.5.1 MySQL 数据库连接

连接 MySQL 时，用户需要填写：

- MySQL 服务器地址。
- 端口号。
- 需要连接的数据库名称。
- 用户名。
- 密码。
- 字符集。

信息填写完成后，用户点击“连接”。服务端尝试连接对应的 MySQL 数据库，连接成功后返回：

1. 当前数据库中所有数据表的名称。
2. 第一张表的表结构。
3. 第一张表的表数据。

客户端随后跳转到 MySQL 交互页面，在预览区域展示第一张表，**并将所有表名填入下拉列表。用户切换表名时，左侧预览数据随之更新。**

连接完成后，用户可以创建会话，使用自然语言与数据库进行交互。

#### 1.5.2 数据库连接复用与断开

如果用户需要断开 MySQL 连接，或希望改为连接其他数据库，可再次点击“智能 DB”导航项，返回数据库连接管理页面。

在已建立连接的信息卡片中，用户可以：

- 点击**使用此连接**，返回对应数据库的智能 DB 交互页面。
- 点击**断开连接**，结束现有数据库连接。

#### 1.5.3 SQLite 数据库连接

SQLite 数据存储在数据库文件中，因此其接入方式与 MySQL 不同。用户需要：

1. 点击“浏览”，从本地选择 SQLite 数据库文件，例如 `xxx.db`。
2. 将选中的 `.db` 文件上传至服务器。
3. 上传成功后点击“连接”。
4. 系统建立 SQLite 数据库连接，进入智能 DB 交互界面。

**两类数据库的主要区别在于连接方式：** MySQL 输入服务器连接参数；SQLite 上传数据库文件。连接成功后的表预览、建会话和自然语言交互操作基本一致。

#### 1.5.4 数据库修改操作与临时表

为了保障数据操作的安全性，**执行修改类 SQL 前，先备份原表，再在备份表中执行 SQL**。

当用户点击预览时，客户端查看备份表的数据，以便观察修改结果。为此，后端需要提供“获取指定连接下临时表列表”的服务接口，前端在需要时发起请求。

#### 1.5.5 智能 DB 涉及的服务端功能

1. 新建数据库连接。
2. 断开数据库连接。
3. 获取数据库表列表。
4. 获取表数据。
5. 获取临时表列表。
6. 上传 SQLite 文件。

### 1.6 我的文件页面

用户点击“我的文件”导航项后，系统切换至文件管理页面，展示当前用户此前上传的文件列表。

针对每个文件，用户可以进行以下操作：

- **预览文件**：Excel 文件进入智能 Excel 页面预览；SQLite 文件进入智能 DB 页面，并建立对应 SQLite 数据库连接以预览数据。
- **下载文件**：从服务器获取文件并保存至用户本地。
- **删除文件**：删除服务器上存储的文件，同时删除与该文件关联的聊天会话。

**涉及的服务端功能：**

1. 获取文件列表。
2. Excel 文件预览。
3. 下载文件。
4. 删除文件。

### 1.7 历史会话页面

用户点击“历史会话”导航项，系统获取并展示此前的聊天会话列表。

用户可以：

1. **查看会话列表**：浏览已经创建的聊天会话。
2. **打开历史会话**：点击某个会话，客户端获取其历史消息，并跳转至对应页面展示完整会话内容。
3. **删除历史会话**：点击会话对应的删除按钮，删除指定聊天会话。

**涉及的服务端功能：**

1. 获取聊天会话列表。
2. 获取指定会话的历史消息。
3. 删除指定聊天会话。

### 1.8 个人信息页面

点击“个人中心”导航项后，系统展示当前用户的个人信息，以及用户上传的文件列表。

此处的文件列表与“我的文件”功能保持一致，支持预览、下载和删除。页面另提供**退出登录**按钮：用户点击后退出本次登录，并跳转至登录页面。

**涉及的服务端功能：** 退出登录。

## 2. 数据分析

### 2.1 用户信息

平台需要维护用户的基本账号信息，主要字段如下：

| 字段     | 用途                     |
| -------- | ------------------------ |
| 用户 ID  | 唯一标识用户             |
| 用户昵称 | 账号展示及昵称登录       |
| 用户密码 | 用于密码登录验证         |
| 用户邮箱 | 用于邮箱登录及验证码接收 |
| 用户状态 | 标记在线、离线状态       |

**密码存储要求：** 原文强调必须保存经过哈希盐值加密处理后的密码结果，不能直接存储明文密码。

### 2.2 会话信息

HTTP 请求本身是无状态的。若每次请求都要求用户重复提交身份信息，会增加操作负担和安全风险。

因此，用户登录成功后，服务端生成临时身份凭证 `sessionId`。客户端在后续请求中携带该凭证，服务端根据 `sessionId` 识别用户身份。用于支持会话登录，并减少重复登录带来的操作。

### 2.3 文件信息

Chat2Data 需要管理两类文件：

1. **Excel 文件**：用于解析 Worksheet，并进一步开展自然语言数据分析。
2. **SQLite 数据库文件**：用于上传并建立 SQLite 数据库连接。

文件管理涉及两部分数据：

- **文件本体**：可以直接存放在服务器磁盘，也可以使用 FastDFS 等分布式文件存储系统管理。
- **文件元信息**：在 Chat2Data 业务系统中单独维护，便于文件查询、管理及关联。

| 字段            | 含义                        |
| --------------- | --------------------------- |
| 文件 ID         | 标识文件                    |
| 文件名称        | 原始或展示名称              |
| 文件大小        | 文件的体积                  |
| 文件后缀        | 文件格式类型                |
| 上传时间        | 文件上传的时间              |
| 所属用户        | 文件归属的用户              |
| 文件关联会话 ID | 与文件关联的聊天会话        |
| FastDFS 存储 ID | 在 FastDFS 中定位文件的标识 |

### 2.4 Worksheet 表列表信息

Excel 文件上传并解析后，各个 Worksheet 的数据会分别写入数据库表。为便于确认一个 Excel 文件关联了哪些数据库表，系统需要维护 **Worksheet 与数据库表之间的映射关系**。

映射信息至少包括：

1. **文件 ID**：指出 Worksheet 所属的 Excel 文件。
2. **Worksheet 名称**：记录 Excel 中工作表的名称。
3. **数据库表名称**：指出该 Worksheet 的数据实际存储在哪张数据库表中。

### 2.5 聊天会话信息

#### 2.5.1 ModelBridge 的内部会话数据

项目采用自己封装的ModelBridge 与模型交互。ModelBridge自行管理聊天会话和会话消息，并将这些数据存储在 SQLite 数据库中。

ModelBridge 内部会话信息主要包含：

- **会话 ID**：唯一标识当前会话。
- **用户 ID**：标识会话所属用户。
- **模型配置 ID**：关联当前会话使用的模型配置。
- **会话标题**：用于展示和区分会话。
- **消息历史**：按顺序保存系统提示、用户消息、模型回复及工具结果。
- **创建时间**：记录会话创建时的 Unix 毫秒时间戳。

这些字段能够管理模型聊天过程，例如，查看某个 Excel 文件相关的聊天会话时，仅有聊天消息还不能确定会话所关联的 **Excel 文件。**

#### 2.5.2 Chat2Data 补充维护的业务会话信息

为支持文件与会话关联，以及数据库交互，业务系统还需要维护自己的聊天会话记录：

| 字段           | 含义                              |
| -------------- | --------------------------------- |
| 聊天会话 ID    | 唯一标识聊天会话                  |
| 用户 ID        | 会话所属的用户                    |
| 会话标题       | 默认取第一条消息的前 20 字        |
| 会话创建时间   | 会话建立的时间                    |
| 最后活跃时间   | 最近一次活跃时间                  |
| 消息数量       | 会话中的消息条数                  |
| 模型名称       | 当前会话使用的模型                |
| 关联文件 ID    | 与会话关联的 Excel 或其他业务文件 |
| 会话类型       | 用于区分不同的会话场景            |
| 数据库连接信息 | 与数据库会话相关的连接信息        |

**核心作用：ModelBridge** 管理模型会话和消息；Chat2Data 补充维护会话与用户、文件、数据库之间的业务关联。

### 2.6 Worksheet 表数据

Worksheet 的实际数据无需预先定义一套统一、固定的数据表结构。

Excel 上传后，服务端需要：

1. 解析 Excel 文件中的每个 Worksheet。
2. 根据工作表中的数据分析其字段与结构。
3. 在数据库中创建与该 Worksheet 对应的数据表。
4. 将该 Worksheet 的数据写入新建的表中。

因此，**数据库表结构依据实际 Worksheet 内容动态生成**，而不是所有 Excel 文件共用同一张固定结构的数据表。
